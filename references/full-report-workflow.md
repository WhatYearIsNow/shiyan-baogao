# 完整实验报告工作流

完整报告、局部章节扩写或交前审查时读取。只算数据时不需要先构造整份目录。

## 1. 先把“要求”与“材料”分开

| 要求来源 | 决定什么 | 使用边界 |
|---|---|---|
| 用户本次交付要求 | 只算、局部、精简完整、全面完整、文件格式 | 不等于允许虚构缺失数据或观察 |
| 本次逐字稿、现场照片、本人观察与用户确认 | 本次实际对象、操作、结果及教师当场变更 | 用于还原实际执行；身份或 ASR 含义不清时确认 |
| 本次指导书/报告纸 | 默认题目、图表、尺寸、字段、问答与顺序 | 未被本次明确变更时是主要约束；保留版本差异 |
| 本次教师口述/批注 | 对指导书的补充、删改、特殊口径 | 必须能定位并与现场证据交叉核对；不凭 ASR 猜 |
| 教材/本次课件 | 原理、定义、公式和标准操作 | 精炼改写，只取本次需要的部分 |
| 往届或已有报告 | 版面、常见结构和教师关注点 | 只作结构参照，不提供本次事实 |

同一材料可以兼有多种作用，但要求、数据/观察、计算依据和展示模板必须分开登记。

冲突裁决按硬顺序执行：**本次教师口径 ＞ 本次课件/教材 ＞ 常理**。要求矩阵逐项标注依据级别；被覆盖的课件/常理条目不删除，其差异集中写进处理说明。

## 2. 建立要求矩阵

在写正文前填写：

| ID | 报告要求原意 | 定位 | 正文位置 | 所需证据 | 状态 |
|---|---|---|---|---|---|
| R01 | 写明实验名称和目的 | 指导书实际页/条目 | 开头 | 本次题目、精炼目的 | 已具备/待核 |
| R02 | 绘制规定对象的观察图并标注字段 | 指导书实际页/条目 | 结果 | 本人观察或照片、材料/工况/倍率等 | 已具备/待核 |

逐项检查对象、数量、图幅/单位、标注字段、结论和思考题。若逐字稿、现场照片或本人观察明确表明本次对象与指导书通用版本不同，矩阵同时记录“指导书默认项”和“本次变更”，按本次实际执行；证据不足时主动确认。已有样板中对象相似但牌号、处理状态或图数不同，不能仅凭样板替换本次对象。

## 3. 选择范围

### 精简完整（默认）

覆盖全部硬要求，只保留支撑操作和结果的必要内容。常见形态是名称与目的 → 必要原理/方法 → 数据或观察结果 → 讨论/结论；具体标题服从要求矩阵。

### 全面完整（用户明确选择）

在精简版基础上补充仪器、原理推导、完整步骤、扩展讨论或思考题。每个新增章节仍须回答“它帮助理解哪项操作、结果或结论”；仅为拉长篇幅的内容删除。

### 局部交付

只写用户要求的章节，同时保留必要输入、来源和结论边界。不要因为已有完整模板而扩展任务。

## 4. 内容生成顺序

1. 完成要求矩阵和来源表。
2. 处理原始数据、观察与图像身份，解决阻断项。
3. 先写结果表/图和结论句，再回写最少必要的原理与步骤。
4. 讨论只解释本次结果：比较、异常、传播路径、模型边界和可执行改进。
5. 删除重复定义、与本次无关的设备百科、泛泛感想和没有结论的段落。
6. 报告正文与说明/溯源相邻交付，但在标题和语气上清楚分层。

## 5. 生成稿自身验收

以下用于生成产物的校验。用户之后提供誊抄或自主修改的报告时，按[誊抄后独立复核](handwritten-review.md)另行检查，不因生成稿验收通过而省略，也不在生成任务中等待誊抄件。

- 身份、课程、实验名称、日期和文件名是否一致。
- 要求矩阵是否每项闭合；指导书默认项与本次课堂/现场变更是否有证据，是否被参考样板悄悄换了对象或数量。
- 原始记录、正文表格、图点、公式代入、最终结果和讨论数字是否逐项一致。
- 参考值、估计值和实测值是否如实标注；同源反算是否被误写成独立验证。
- 观察图是否来自本次观察；教师/教材图是否有来源性质；图注要求字段是否齐全。
- 精简是否删掉了硬要求，全面是否加入了无关长段。
- PDF 是否全页可读、无裁切、无空结果、无错误身份，必要附件和签字页是否完整。
